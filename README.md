# Домашняя работа 1. Аналитическая модель небольшой CNN

Модель оценивает число операций, пик памяти, время и энергию одного прямого прохода в зависимости от размера квадратного изображения `S` и размера батча `B`. Сеть задана в `models.py`, формулы — в `equations.py`, рукописный вывод — в `hw1_handwritten.pdf`.

## Оборудование и воспроизведение

Измерения получены на NVIDIA GeForce RTX 5060 Ti (16 ГБ), Windows. Использовались Python 3.11.6, PyTorch 2.11.0+cu128, cuDNN 9.19, NumPy 2.4.6, SciPy 1.17.1 и `nvidia-ml-py` 13.615.71. Полный список пакетов находится в `requirements-lock.txt`.

Команды для PowerShell из корня репозитория:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt --index-url https://pypi.org/simple --extra-index-url https://download.pytorch.org/whl/cu128
.\.venv\Scripts\python.exe measure.py --results results_repeat
.\.venv\Scripts\python.exe calibrate.py --results results_repeat
```

Новая папка `results_repeat` сохраняет опубликованные измерения в `results/`. Для пересчёта прогнозов по уже сохранённой таблице GPU не нужна: `python calibrate.py --results results` (это также заново подбирает параметры). После изменения исходного кода новые измерения следует проводить в отдельной папке: при продолжении старого запуска `measure.py` сверяет хеши файлов.

В `results/measurements.csv` находятся измерения, в `results/theta.json` — подобранные коэффициенты, в `results/figures/` — сравнение прогноза с измерениями. `results/metadata.json` содержит сетку эксперимента и настройки, необходимые для повторной обработки данных.

## Формулы и допущения

Для `S`, кратного 16, и положительного целого `B`:

| Величина | Формула | Единица |
|---|---|---|
| FLOPs `F` | `B(17712S² + 313344)` | FLOP |
| Пик памяти `M` | `4161296 + 68BS²` | байт |
| Логический объём данных `D` | `364BS² + 8592B + 4161296` | байт |
| Время `L` | `t0 + max(F/R, D/W)` | с |
| Энергия `E` | `P0·L + eF·F + eD·D` | Дж |

В `F` учитываются умножения и сложения свёрточных и полносвязных слоёв: один MAC равен двум FLOPs. Операции ReLU, MaxPool и GlobalAvgPool в эту оценку не входят. В модели 1 040 324 параметра FP32, то есть 4 161 296 байт.

`M` оценивает пик `torch.cuda.max_memory_allocated()` при одном проходе. На этапе MaxPool одновременно находятся вход, выход первой свёртки, выход пула и временные индексы `int64`: `4(3+8+2)BS² + 8·2BS² = 68BS²` байт. Рабочие буферы свёрток и служебные выделения PyTorch в формулу не включены.

`D` складывает однократные логические чтения и записи основных активаций и весов, включая чтение и запись для ReLU. Временные индексы MaxPool и внутренние буферы в `D` не входят; это допущение о модели трафика, а не измерение обмена с памятью GPU. Поэтому индексы учтены в пике `M`, но не меняют `D`.

Коэффициенты `t0` (с), `R` (FLOP/с), `W` (байт/с), `P0` (Вт), `eF` (Дж/FLOP) и `eD` (Дж/байт) подбираются по измерениям. Численные значения сохранены в `theta.json`. Память и FLOPs не подгоняются.

## Измерения и результаты

Использовались случайные входы FP32, `eval()` и `torch.inference_mode()`. Выключены `cudnn.benchmark`, TF32 для cuDNN и матричного умножения. Время — медиана 31 прохода после 10 прогревов, с синхронизацией CUDA. Память — абсолютный пик PyTorch после сброса счётчика пика перед отдельным проходом. Энергия — показание счётчика NVML для всей GPU, делённое на число проходов; взята медиана трёх окон. Фоновая нагрузка GPU отдельно не вычиталась.

Основная сетка: `S = 32, 64, 128, 224, 256, 384, 512`; `B = 1, 2, 4, 8, 16, 32, 64, 128, 256`. Добавлены `S = 400, 416, 432, 480` и `B = 134, 203, 248`. Основные 63 сочетания использовались для калибровки, остальные 69 — только для проверки. Всего измерено 132 сочетания, OOM не было. При OOM код сохраняет статус точки вместо численных измерений.

Средняя абсолютная процентная ошибка (MAPE) на проверочных точках:

| Показатель | MAPE |
|---|---:|
| Время | 12,96 % |
| Память | 16,78 % |
| Энергия | 6,97 % |

Время подбиралось минимизацией относительной ошибки, энергия — регрессией с неотрицательными коэффициентами. Для полученного решения `t0 ≈ 0,261 мс`, `W ≈ 145 ГБ/с`, `P0 ≈ 42,3 Вт`, `eF ≈ 2,13·10⁻¹¹ Дж/FLOP`, `eD = 0`. Ветвь `D/W` оказалась больше `F/R` на всех точках, поэтому отдельное значение `R` из этого набора надёжно определить нельзя. Нулевой `eD` также не означает отсутствия затрат энергии на передачу данных.

Модель памяти лучше совпадает с большими конфигурациями: для `(S, B) = (512, 256)` прогноз составляет 4 567 564 048 байт, измеренный пик — 4 577 132 544 байта. На малых размерах вклад неучтённых буферов относительно больше. Все точки поместились в память GPU, поэтому положение границы OOM проверить не удалось.

На небольших батчах заметны накладные расходы запуска и разброс времени. В полученной аппроксимации разделить режимы ограничения пропускной способностью и вычислениями не получилось: `F` и `D` меняются похоже, а модель использует одну ветвь `max`. Энергия измерялась для серии проходов и всей GPU, поэтому влияние фоновых процессов также остаётся в данных. Графики в `results/figures/` показывают измеренные значения вместе с прогнозами.
